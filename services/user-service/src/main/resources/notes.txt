# 🧠 1. SOLID Principles (Mapped to YOUR code)

## ✅ S — Single Responsibility Principle

Each class has a clear responsibility:

* `UserController` → HTTP layer only
* `UserService` → business orchestration
* `KeycloakService` → external identity provider integration
* `UserRepository` → persistence

👉 Example:

```java
UserService → orchestrates DB + Keycloak
```

It does NOT:

* Handle HTTP
* Handle JWT parsing
* Handle DB queries directly

✔ Clean separation

---

## ✅ O — Open/Closed Principle

Your system is open for extension, closed for modification.

Example:

```java
implements IdentityProviderService
```

👉 You can replace Keycloak with:

* Auth0
* Cognito
* Custom IDP

Without changing `UserService`

---

## ✅ L — Liskov Substitution Principle

```java
IdentityProviderService → KeycloakService
```

Any implementation can replace another without breaking behavior.

👉 Interview line:

> “UserService depends on abstraction, not concrete implementation.”

---

## ✅ I — Interface Segregation

You didn’t create a fat interface.

Instead:

```java
IdentityProviderService
```

Contains only relevant methods:

* createUser
* deleteUser
* enable/disable

👉 Not overloaded → clean

---

## ✅ D — Dependency Inversion (VERY IMPORTANT)

```java
private final IdentityProviderService identityProviderService;
```

👉 High-level module (`UserService`)
does NOT depend on low-level module (`KeycloakService`)

✔ Depends on abstraction

---

# 🧩 2. Design Patterns You Implemented

This is where you score high in interviews.

---

## 🔥 1. Saga Pattern (Orchestrated)

In `UserService`:

Flow:

1. Create user in Keycloak
2. Save in DB
3. If DB fails → rollback Keycloak

👉 This is:

> **Compensating transaction (Saga pattern)**

---

## 🔥 2. Adapter Pattern

```java
KeycloakService implements IdentityProviderService
```

👉 You adapted Keycloak API to your internal interface

---

## 🔥 3. Facade Pattern

`UserService` acts as:

> A single entry point for complex operations

It hides:

* DB logic
* Keycloak logic
* Mapping logic

---

## 🔥 4. Template / Strategy (via Spring + Resilience4j)

Using:

* Retry
* Circuit breaker

👉 Behavior changes without modifying logic

---

## 🔥 5. Repository Pattern

```java
UserRepository extends JpaRepository
```

👉 Abstracts DB operations

---

## 🔥 6. DTO Pattern

```java
UserRequestDto
UserResponseDto
```

👉 Separation of:

* Internal entity
* External API contract

---

## 🔥 7. Mapper Pattern

```java
UserMapper
```

👉 Converts:

* DTO ↔ Entity

---

## 🔥 8. Circuit Breaker Pattern

Using:

* Resilience4j

👉 Prevents cascading failures

---

## 🔥 9. Retry Pattern

Also via Resilience4j:

* Handles transient failures
